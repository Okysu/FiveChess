# 内容作者须知（并行写作规则）

你是《命阙》的资深卡牌内容设计师。规则引擎已完成且数据驱动，你的任务是编写内容 JSON。

## 必读
1. `docs/游戏设计文档.md`：规则、关键词、状态、世界观。
2. `docs/内容DSL.md`：JSON DSL 的**唯一权威**说明。
3. `src/engine/defs.ts`：类型定义；不确定语义时查 `src/engine/combat/core.ts` 的 `execEffect`。
4. `tests/fixture.ts`：小型示例。

## 规则
- **只创建/编辑分配给你的文件。** 其他 agent 正在并行编写其他文件，不要碰它们。`npm run validate` 报出的**不属于你的文件**的错误请忽略。
- **只能使用 DSL 文档列出的 op / 选择器 / 条件 / 触发器。不要修改引擎代码。** DSL 表达不了的设计，就重新设计这张牌。
- 名称与文本一律简体中文，原创、有意境；**不照搬**炉石/万智牌/杀戮尖塔/三国杀的名称与术语。
- 规则文本必须与实际行为完全一致；关键词/状态用 `[术语]`，数字用 `{var}`（出现在文本里的数值都要是 vars，这样升级与增减益能正确显示）。
- `art.subject`：英文 1–2 句，写主体、姿态、构图、光线；不写风格词，不要求任何文字。
- 已约定的共享 ID（可直接引用）：
  - 主帅：`r_huojin` 霍烬、`r_liyuan` 离鸢、`b_shiyun` 石韫、`b_suxian` 素弦、`g_qingsi` 青姒、`g_acang` 阿苍、`y_xuanji` 玄机子、`y_yanwujiu` 燕无咎、`p_yetan` 夜昙、`p_liuxu` 柳絮
  - 状态牌（由中立作者创建，敌人意图可 `create` 进玩家牌组）：`st_wound` 伤口、`st_dazed` 恍惚、`st_burn_scar` 灼痕、`st_toxin` 蚀毒、`st_frost` 霜噬；诅咒 `cu_suye` 宿业
- 自检：
  ```bash
  npm run validate
  npx vitest run tests/content.test.ts -t <你的ID前缀>
  ```
  修到你的文件零错误、冒烟测试全部通过为止。
- 质量标准：成熟商业构筑卡牌的深度。每张牌都有存在理由，构筑方向可成型，协同明确，没有废牌；在合适处与 **献牌为源 / 应对窗口与余烬 / 天命判定 / 双排战线** 咬合。
- 完成时回复 ≤200 字总结：写了哪些文件、数量、构筑方向、DSL 无法表达的设计（如有）。
