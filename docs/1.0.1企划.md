# 命阙 1.0.1 企划 · 命书续章

状态：已定，开始开发（2026-09-26）。本版只做 P0，其余进入后续版本。

## 已定的原则

- **局外不给永久数值**，只做横向成长：更多选择、更多打法、更多目标。
- 美术一律用 `gpt-image-2` 生成（合图 + 切图省调用），不用 2.5 系列。
- 三端（网页 / PC / 安卓）同一套代码；**GitHub 上推 `v` 开头的 tag 时，Actions 自动构建 PC 安装包与 APK 并生成 Release**。

## 现状诊断

- 体量：卡牌 359、主帅 10、副将 20、遗物 94、丹药 26、事件 42、敌人 96、遭遇战 77、逆命 15 级。
- 命数只是一条解锁轨道：一局约 300–450，约 12 局走完 4300 的全部解锁，之后命数没有用处。
- 长期目标只剩逆命与图鉴。

## P0 内容

### 1. 版本号与更新日志（三端统一）

- 版本号只有一个来源：`package.json` 的 `version`。网页构建时注入，Electron 安装包直接读取，安卓 `versionName` / `versionCode` 由 Gradle 从同一处读取。
- 日志只维护一份：`src/data/changelog.json`（版本、日期、标题、「新增 / 平衡 / 修复」，每条可标平台），同时生成仓库根目录 `CHANGELOG.md`。
- 游戏内：标题页角落显示版本号；更新后首次启动弹出「命书新章」，只列上次看过之后的条目；「设置 → 通用」可随时查看全部日志。
- 平衡改动写成「旧值 → 新值」。

### 2. 发版：GitHub Actions

- 触发：推送 `v*` tag（例如 `v1.0.1`）。
- 校验 tag 与 `package.json` 版本一致，不一致直接失败。
- Windows 任务：`npm run desktop:pack` → 安装包 + 免安装版。
- 安卓任务：JDK 21 + Android SDK 36 → APK。配置了签名密钥（仓库 Secrets）就出正式签名包，否则出调试签名包。
- 汇总任务：从 `changelog.json` 取出该版本的日志作为 Release 说明，附上全部安装包。

### 3. 开局祈命

- 每局开始（教程局除外）从 3 个「命签」中选 1 个；每个命签都是「好处 + 代价」，也有少数只有小好处的「小吉」。
- 逆命 10 及以上只给 2 个选择。
- 首批 15 个命签：开局可用 6 个，其余 9 个由延长后的命数轨道解锁（5000 / 7000 / 9500 各 3 个，12000 为收尾称号）。命数走完原轨道后仍有目标。

### 4. 主帅精通

- 每位主帅各自积累精通（该主帅每局得到的命数），共 10 级，约 15 局满级。
- 奖励（全部是横向的）：

| 等级 | 奖励 |
|---|---|
| 2 | 称号 |
| 3 | **第二件起始遗物**，开局可在两件之间选择 |
| 5 | **「另一面」技能**：替换该主帅的一个技能，换一种打法 |
| 6 | 称号 |
| 8 | 用该主帅开局时，祈命多一个可选命签 |
| 10 | 称号 + 主帅选择页的精通印记 |

- 10 件第二起始遗物 + 10 个「另一面」技能，逐一用模拟器验证不超过原版强度区间。
- 存档：Profile v1 → v2，按已有对局记录补发精通经验，老玩家不丢进度。

## 后续版本（不在 1.0.1）

## 风险

- 精通与祈命都会改变平衡：每个命签、每件遗物、每个「另一面」都用模拟器过一遍，结果记入 `docs/难度评估.md`。
- 存档升级必须可回退：迁移函数有单元测试，旧存档读入后字段齐全。
- 安卓签名：调试签名包之间可以覆盖安装，但 CI 与本机的调试密钥不同，两者不能互相覆盖；正式签名密钥配置进 Secrets 后统一。
