# 《命阙》UI 研究笔记

> 版本 0.1 · 研究阶段产出，用于指导 PixiJS 表现层实现。
> 设计分辨率 **1920×1080（16:9 横屏）**，桌面 + 移动横屏。下文所有像素（记作 px 或 dpx = design px）均指设计分辨率坐标；时间单位 ms。
> 术语以 `docs/游戏设计文档.md`（GDD）为准：五色 赤/玄/青/金/紫 + 素；命纹 日/雷（阳）、月/山（阴），点数 1–13；关键词【远射】【奇袭】即任务描述中的“远程/突袭”。
> 引用格式：`[Sx]` 对应文末“参考来源”编号。部分来源仅能读到搜索摘要（页面 403/404），已在来源表中标注。

## 0. 总体结论（先读这一节）

1. **战场采用“左右对垒”横向布局**（我左敌右，主帅在各自最外侧，前阵在中线两侧），而不是炉石式上下布局。16:9 横屏的水平空间是垂直空间的 1.78 倍，上下布局需在 1080px 里塞下 6 条阵列 + 手牌，每条 ≤110px，不可读。左右布局还契合东方“手卷”构图与杀戮尖塔“我左敌右”的惯例。
2. **前阵 4 格、后阵 3 格做“错位竖列”**：后阵每格的纵向中心落在前阵两格之间，恰好把 GDD 4.2 的“对位相邻”（前 0-1↔后 0、1-2↔1、2-3↔2）画成几何关系，无需额外连线说明。
3. **信息分五级**：常驻数字 → 悬停内联预览 → 关键词提示框 → 检视大图 → 战报抽屉。任何一级都不能挡住上一级的信息。
4. **“签名时刻”只有两个会中断节奏**：天命判定翻牌（居中，约 1.9 s）和应对窗口（仅在有可支付应牌时出现，默认 8 s 倒计时）。其余演出都应可被加速/跳过。
5. **颜色从不单独承载信息**：五色源、四命纹、意图类型都“颜色 + 形状/图标”双编码 [S40]。
6. **移动端不是缩放版**：屏幕高 < 500pt 时切换“紧凑档”布局，触控热区 ≥ 44pt（约 122 dpx，见 §15.1 换算）[S41][S42]。

## 1. 卡面构成

### 1.1 参考游戏怎么做的

- **炉石传说**：费用固定在左上角法力水晶；随从攻击力左下（黄色剑形）、生命右下（红色血滴），武器为攻击/耐久；名称横幅穿过画面下沿，稀有度宝石在画框底部正中（传说为橙色，另有龙形边框）；**卡牌类型靠画框形状区分：随从椭圆、法术矩形、武器圆形** [S19][S21][S45]。GDKeys 的对比分析指出炉石把费用、攻击、生命做成“溢出卡框”的大号数字，并把描述性内容放进悬停提示，优先保证数字可读 [S4]。
- **杀戮尖塔**：费用在左上角能量球；**稀有度靠名称横幅与卡框颜色（灰/蓝/金）**；**卡牌类型靠插画框形状**：攻击为五边形、技能为矩形、能力为圆形 [S24]。
- **万智牌 Arena**：沿袭实体卡模板，费用由“通用数字 + 彩色法术力符号”组成，位于右上；颜色是法术力类型 [S43][S4]。
- **符文之地传说**：单位卡整幅插画，法术卡换成完全不同的模板以示区分；数值嵌入卡框内部 [S4]。关键词有专属图标，多关键词时有时只显示图标 [S46]。
- **邪恶冥刻**：低分辨率画面下为了可读性，卡面只保留生物名称，用图标（印记）覆盖在立绘上传达能力，而非文字 [S35]。

### 1.2 为什么这样做

- **数字最先被读**：出牌决策 90% 看“付不付得起 + 打多少 + 扛多少”，所以费用、攻击、生命必须在最小尺寸下仍可辨认，且位置恒定（角落）以建立肌肉记忆 [S4]。
- **类型用轮廓而非文字**：画框形状在缩略状态下仍然可辨，远比“类型行”小字可靠（炉石/尖塔的共同做法）[S19][S24]。
- **稀有度用颜色 + 位置固定的宝石**：玩家在奖励界面扫视时只需看一个点。
- **规则文字是最先牺牲的**：小尺寸下改用关键词图标（冥刻、LoR），文字留给悬停/检视 [S35][S46]。

### 1.3 本作怎么做

**母版比例 5:7**，美术母版 400×560（2× 于手牌尺寸），各尺寸档：

| 档位 | 尺寸 (dpx) | 使用场景 | 保留的信息 |
|---|---|---|---|
| L0 检视 | 480×672 | 右键/长按检视、图鉴 | 全部，含风味文字、升级对比 |
| L1 悬停 | 300×420 | 手牌悬停、奖励悬停 | 全部规则文字（正文 19–20px） |
| L2 手牌 | 200×280 | 桌面手牌、商店 | 费用+色点、名称、插画、攻/体、【应】印、关键词图标；正文 13px（桌面勉强可读） |
| L3 网格 | 150×210 | 牌库查看、三选一缩略 | 同 L2，去掉类型行 |
| L4 迷你 | 120×168 | 移动端手牌、战报 | 费用+色点、插画、攻/体、【应】印、色框；**无正文** |

**元素布局（以宽 W、高 H 的百分比表示，L2 下括号为 px）：**

```
┌──────────────────────────────┐
│(●2)(赤)(赤)          [应]印  │ ← 费用盘 Ø0.26W(52) 左上；色点 Ø0.12W(24) 横排紧随；【应】朱印 0.22W 右上
│ ┌──────────────────────────┐ │
│ │                          │ │ ← 插画窗 x 6–94%W, y 6–54%H（≈176×134，约 4:3）
│ │   插画（窗形随类型变化）   │ │   窗形：随从=拱顶 / 策略=卷轴矩形 / 应对=菱角矩形
│ │                   [远射] │ │        装备=圆扇 / 延时=沙漏腰形 / 阵地=横幅宽窗
│ └──────────────────────────┘ │   关键词图标贴插画窗右下，最多 3 个，Ø0.14W(28)
│▓▓▓▓▓▓▓▓ 名 称 横 幅 ▓▓▓▓▓▓▓▓▓│ ← y 52–62%H，名称 17px（6 字以上自动缩至 14px）
│            ◆稀有度            │ ← 宝石 Ø0.08W 压在横幅下沿正中
│        随从·妖  ／ 策略        │ ← 类型行 y 63–68%H，11px（L3 以下隐藏）
│  规则文字区 y 68–90%H，        │ ← 13px@L2 / 19.5px@L1，最多 4 行；关键词加粗着色
│  x 8–92%W                     │
│(⚔3)                      (♥4) │ ← 攻/体盘 Ø0.24W(48)，中心 (10%W, 93%H)/(90%W, 93%H)，溢出卡框 6px
└──────────────────────────────┘
  色框：边宽 0.03W，颜色=流派色；双色卡左右对半渐变；素卡为素白描金
```

- **费用读法**：`通用数字盘 + 色点`，与 GDD 的 `2+赤` 同序。色点 ≤3 个平铺；≥4 个同色时折叠为“赤×4”胶囊。色点形状编码（示例，最终以美术为准）：赤=火焰菱、玄=方印、青=叶形、金=星芒、紫=新月、素=空心圆。
- **可支付状态**（手牌中实时）：可付 → 费用盘描金亮边；缺通用 → 数字变灰红；缺某色 → 该色点显示为虚线空槽并轻微呼吸（1.2 s 周期），**直接告诉玩家缺的是哪一色**。
- **【应】印**是本作最重要的小尺寸识别点：敌方回合里玩家要在 L4 尺寸下一眼找到应牌，所以用高饱和朱印 + 固定右上角，与任何流派色都不冲突。
- **稀有度**：普通=素铜、稀有=青玉、史诗=紫晶、传说=赤金（宝石颜色 + 横幅纹样繁简双编码）；传说卡另加卷云纹外框（对应炉石龙框的“远看就知道是传说”作用 [S45]）。
- **升级卡（+）**：名称后缀“+”，变化的数值/文字用翠绿色；检视时可按住 Shift 对比原版。
- **阵地卡**为横版 7:5，放入阵地位时不需再变形。

## 2. 手牌

### 2.1 参考游戏怎么做的

- **炉石**：手牌在屏幕下沿扇形排开，上限 10 张 [S18]；手机版把手牌只露出一半，**点击手牌区先整体放大**再选牌，长按单卡全屏查看 [S23][S22]。
- **杀戮尖塔**：手牌上限 10，扇形；悬停时卡牌放大上移、邻卡让位 [S26]。社区复刻的 Godot 实现给出常用参数：最大旋转 ≈0.2 rad、卡间重叠 −60px、悬停时邻卡位移 80–150px、弧高 20–60px、悬停放大 1.2–2.0×，并强调“防闪烁” [S37]。
- **符文之地传说**：手牌几乎只露出屏幕边缘，棋盘让给单位区 [S4]。
- **一个反面教材**：Grama Online 的开发日志记录了扇形 + 邻卡让位导致的**悬停自我失效**——卡片让位后鼠标不再落在卡上，于是弹回、再次悬停，形成闪烁循环；作者最终退回直线排列，并列出了解法：悬停宽限区、锁定悬停、代理热区、视觉位移与交互边界解耦 [S36]。

### 2.2 为什么这样做

- 扇形让 10 张牌共享 ~1200px 宽度仍能露出每张的左上角费用（最关键信息）。
- 悬停放大是“按需展开”：常态省空间，关注时给全文。
- 邻卡让位是为了让放大后的卡不遮挡左右邻居的费用角，方便横向比较。
- 移动端没有悬停，所以炉石把“查看”拆成了两步（点区域放大 → 长按全屏）。

### 2.3 本作怎么做

**桌面参数（1920×1080）**

| 参数 | 值 |
|---|---|
| 手牌区 | x 380–1540（宽 1160），卡片常态中心 y = 980（卡顶 840，底部 20px 出屏） |
| 卡片间距 | `pitch = min(150, (1160 − 200)/(n − 1))`：5 张 = 150，8 张 = 137，10 张 = 107（重叠 46%） |
| 扇形 | 虚拟圆半径 R = 2400；单卡角度 `θi = (i − (n−1)/2) × min(4°, 28°/(n−1))`；y 沿圆弧下沉 |
| 悬停 | 缩放 1.5×（300×420），旋转归零，底边贴 y=1080（卡顶 660），120 ms ease-out-cubic |
| 邻卡让位 | ±1 位移 70px，±2 位移 35px，±3 位移 12px；同 120 ms |
| 热区 | **使用常态布局计算的静态热区**（解耦视觉与交互，[S36] 方案），并在切换悬停目标时加 60 ms 宽限，杜绝闪烁 |
| 抽牌 | 从左下牌库飞入，单张 250 ms，多张间隔 80 ms；手满 10 张时多抽的牌飞向弃牌堆并显示“手牌已满” |
| 弃牌 | 回合结束整手扫向右下弃牌堆，间隔 40 ms，总长 ≤ 600 ms |
| 可打出高亮 | 可支付且有合法目标的牌：卡框外 4px 金色描边；【应】牌在我方回合也照常高亮 |
| 【藏锋】牌 | 回合结束时不飞走，卡顶出现“藏”字小签；【浮光】牌卡面有流光纹，回合末化灰燃尽 300 ms |

**大手牌压缩**：n ≥ 8 时角度步长降至 28°/(n−1)，且悬停放大改为 1.6×，确保被压缩的卡在悬停时完全可读；n = 10 时额外在手牌区左端显示“10/10”满手提示。

**拖拽中**：卡片被拖离手牌区上沿（y < 800）后，其余手牌下沉 60px、透明度 70%，把棋盘让出来。

**移动端（紧凑档）**：
- 手牌常态缩为 L4（120×168）并只露出上 60%（炉石手机方案 [S23]）。
- **点手牌区**：整排升起并放大到 L2，棋盘上方蒙 20% 暗层；再点空白处收起。
- **点单卡**：选中（上抬 40px，下方弹出“详情条”显示全文，不遮挡棋盘上半）；再点同卡或向上拖 = 出牌。
- **长按 350 ms**：全屏检视 L0，松手关闭。
- 不做扇形旋转（小屏上旋转文字难读），改为直线排列 + 轻微弧度（弧高 12dpx）。

## 3. 出牌与指向

### 3.1 参考游戏怎么做的

- **炉石**：拖牌出手；指向性法术/随从攻击时从源头拉出**带箭头的弧形指示线**，悬停合法目标时准星锁定；这是一类被广泛复刻的交互（Construct、Unity 社区都有“Hearthstone 式箭头”教程）[S47]。费用不足时卡牌不可拖出并播报“法力不足”。
- **炉石的关键词/可交互高亮**：可攻击的随从带绿色光圈，回合内“无可做之事”时结束按钮变绿 [S18]。
- **符文之地传说**：出牌、攻击声明都走拖拽；**先知之眼**在法术/攻击排队时打开，悬停即可预览“若全部结算后的棋盘”；遇到随机效果则直接关闭预览，不做概率呈现 [S13][S14]。
- **三国杀**：出牌是“点手牌 → 点目标武将 → 点确定”的三段式，适合触屏（本作移动端借鉴）。

### 3.2 为什么这样做

- 拖拽 = 实体卡牌的“打出”隐喻；弧形箭头把“谁 → 谁”可视化，且弧线不会被中间单位遮挡。
- 合法目标高亮把规则判断交给界面（本作的“前阵挡近战”规则尤其需要）。
- 先知之眼式预览减少“算错一步”的挫败感，但对随机性保持诚实。

### 3.3 本作怎么做

**无目标牌（策略/献以外）**：拖过“出牌线” y = 760 后，卡片吸附到出牌预备位（x 960, y 560, 1.0×），卡框变亮金，松手即打出；拖回手牌区或按右键/Esc 取消。

**随从牌**：拖动时我方所有**空格**显示落位框（前阵/后阵分别用“剑/旗”底纹提示），悬停某格时出现单位虚影与相邻格统御光环预览；前阵已满/后阵已满时对应列整体变灰并提示“前阵已满”。

**指向牌与攻击**：
- 卡片越过出牌线后停在预备位，从卡片上沿中心拉出**二次贝塞尔箭头**：起点 P0 = 卡顶中心，终点 P2 = 指针，控制点 P1 = 两点中点向上偏移 `0.35 × |P2−P0|`（最大 260px）。
- 箭头由 14 节“燕尾”段组成，沿曲线 600 ms 循环流动；箭头头部 36px。
- 颜色语义：中性 = 米白；悬停合法目标 = 朱金 + 目标处出现“准星印”；悬停非法目标 = 灰色 + 箭头头部变 ✕，并在目标旁 400 ms 后显示原因（如“前阵尚有单位，近战无法选中后阵”“目标具有【隐匿】”“须优先攻击【坚守】单位”）。
- **合法目标**：外圈 3px 金色描边 + 1.2 s 呼吸；非法目标降至 55% 亮度。
- **伤害预览**（见 §12）：悬停合法目标时，目标血条出现“虚影扣减”，数字显示最终伤害；会致死时血条旁出现骷髅/断刃图标；攻击单位时同时预览我方单位受到的反击（除非【远射】）。
- **确定性预览**：对仅依赖确定性结算的操作，预览完全精确（GDD 13 确定性）；若含判定，则预览区显示“需判定”命牌图标，并列出成功/失败两种结果（类似 LoR 在随机时关闭先知之眼的诚实原则 [S14]，但我们给出分支而不是直接关闭）。

**费用不足**：
- 手牌中该卡费用盘为灰，缺失色点呈虚线（§1.3）。
- 若仍尝试拖动：卡片在原位水平抖动 3 次（总 240 ms，振幅 8px），费用盘闪红，左下源盘里**缺失的颜色槽**闪烁，并弹出 1.2 s 小字提示“缺少 1 枚赤源”/“源不足（需 3，余 2）”。不播放打断性的语音。
- 余烬情形：我方回合里余烬不存在；敌方回合应对窗口中，若应牌因余烬不足无法支付，则该牌根本不高亮。

**自动支付可视化**：悬停/拖动一张牌时，源盘中**将被消耗的源**上浮 6px 并描白边（GDD 4.4“表现层会高亮将被消耗的源”）；可按住 Alt 手动点选支付源（高级选项，默认关闭）。

**键盘**：1–0 选手牌，Tab / 方向键循环合法目标，Enter/空格确认，Esc 取消。

**移动端**：点卡选中 → 合法目标高亮 → 点目标 → 目标上方出现“确认”气泡（防误触，可在设置关闭）→ 点确认。也支持拖拽。

## 4. 场面单位

### 4.1 参考游戏怎么做的

- **炉石**：卡牌落场后变为**椭圆肖像 token**，只保留攻击（左下）与生命（右下），能力完全以视觉特效表达：嘲讽 = 盾形边框，圣盾 = 金色护罩，亡语 = 肖像下方骷髅，触发效果 = 闪电图标，剧毒 = 绿瓶，吸血 = 紫色破心，潜行 = 阴影覆盖，冻结 = 冰层；悬停随从显示关键词说明 [S20]。关键词悬停约 1 秒后出说明 [S20]。
- **符文之地传说**：单位在后排与战场都以**缩小的整卡**呈现，保留卡面结构 [S4][S12]。
- **怪物火车**：每层楼有容量点数，单位卡顶部以黄点标注体积 [S38]。
- **三国杀**：长期状态以“置于武将牌上/旁的牌”表达，替代实体版需要记忆的旋转/翻面标记 [S31]。

### 4.2 为什么这样做

- 炉石肖像：场上 14 个单位时，只留两个数字 + 轮廓特效最省空间，且特效是“全局可见”的（远看就知道谁有嘲讽）。
- LoR 迷你卡：保留卡面让“这是哪张牌”一目了然，但更占空间。
- 本作单位需要显示的东西比炉石多：攻/体、关键词（25 个中约 10 个与单位相关）、状态层数（10 种）、延时牌（每目标至多 3 张）、“已行动/未行动”。

### 4.3 本作怎么做：“竖式立牌” token

尺寸 **112×136**（前阵格距 146px，见 §14 线框）。

```
   ┌─[坚][远][灵2]─┐   ← 关键词条：最多 3 个 Ø24 图标，多余显示 +n；灵障以“层数气泡”形式
   │               │
   │  立绘半身裁切  │   ← 与卡面插画同源，取头胸部，上下羽化
   │               │◀ 状态列：右缘竖排 Ø22 图标+层数（灼3 / 毒2 / 冰1 / 易1），最多 4 个，+n
   │(⚔4)     (♥5) │   ← 攻/体 Ø40，字号 24，黑描边 3px
   └──[⌛2][⌛1]────┘   ← 延时牌小签：沙漏 + 剩余回合，悬停看判定条件
```

- **数值颜色**：基础值白色；高于基础（增益）翠绿；生命受损（低于上限）朱红（沿用炉石惯例）。
- **轮廓特效（全局可见，不需悬停）**：【坚守】= 单位底座加一块厚重石质盾座（最显著，直接影响敌方目标选择）；【灵障】= 半透明金色符箓罩（层数气泡在右上）；【隐匿】= 墨色烟雾覆盖 60%；冰冻 = 冰裂叠层；眩晕 = 头顶旋转星；封印 = 符纸贴封 + 关键词条变灰。
- **行动状态**：可攻击 = 底座有流动金线；已攻击/入场当回合 = 立绘去饱和 35%，底座金线消失；【连斩】剩一次时显示“×1”。
- **目标深度提示**：不常驻显示。拖动近战攻击时，敌方不可选中的后阵单位直接变暗（§3.3），而不是在每个单位上挂“深度数字”。
- **悬停**：token 旁（朝向屏幕中线一侧）弹出 L1 卡面 + 关键词/状态提示框（§12）。
- **卡 → token 变形**：出牌松手后卡片飞向目标格（220 ms），在落点处卡框向内“收卷”为立牌（180 ms，卡面插画保持连续，只裁切），落地轻微下压 1.05→1.0（80 ms）并扬起墨尘。总计 ≈ 480 ms；传说单位另见 §13。
- **单位死亡**：立牌碎为墨点散开 350 ms；有【遗志】时先在单位上闪现遗志图标 200 ms 再结算。

## 5. 回合结束按钮

### 5.1 参考游戏怎么做的

- **炉石**：结束按钮在棋盘右侧；**当玩家已做完所有可行动作，按钮亮起明亮的绿色光晕**（常伴随“工作完成”语音）；回合时长 75 s，剩约 20 s 时棋盘上出现燃烧的“绳子”倒计时 [S18]。
- **符文之地传说**：同一个按钮随状态切换文案：“跳过（Pass）/攻击（Attack）/结束回合（End Round）/不格挡（Skip Block）/确定（OK）” [S15][S16]。双方连续“跳过”才结束轮次 [S16]。
- **万智牌 Arena**：右下主按钮随阶段变为“下一步/结算/无攻击者/结束回合”等，空格键即“传递优先权”，Enter“传递直到有可回应之事” [S8]。

### 5.2 为什么这样做

- 用“按钮亮起”取代弹窗确认：告诉玩家“你没有剩余选项”但不强迫他结束，既降低遗漏又不打断。
- 单一主按钮多态化，减少玩家视线跳动（一个位置解决所有“推进流程”的操作）。

### 5.3 本作怎么做

位置：右下 **x 1660–1880，y 790–870（220×80）**，快捷键 空格 / E。

| 状态 | 条件 | 外观 | 文案 |
|---|---|---|---|
| 可行动 | 仍有可支付手牌 / 本回合未献牌且手中有牌 / 有可攻击单位或主帅 / 有可用主动技能 | 墨色底、金字，静态 | 结束回合 |
| 已无行动 | 以上全部为否 | 朱金描边，1.6 s 呼吸光晕 + 一声轻磬（可关） | 结束回合 |
| 仅剩献牌 | 只剩“献牌”这一可行动作 | 同“可行动”，按钮左上出现小“献”字角标 | 结束回合 |
| 敌方回合 | 敌方行动中 | 灰蓝底，禁用；下方显示“敌方行动 2/5” | 敌方回合 |
| 应对中 | 应对窗口打开 | 按钮被“不应对”按钮替换（§6） | 不应对 |
| 选择中 | 观星/弃牌/选目标等子流程 | 变为确定按钮 | 确定 |

- **不做强制确认**。设置里提供“仍有未使用的献牌/可攻击单位时结束回合需二次确认”（默认关）。
- 结束回合时若有余烬生成，按钮上方飘出“余烬 ×2”并飞向源盘（400 ms），强化“留源 = 敌方回合可应对”的因果。
- 无回合计时（单机），但保留“结束回合”后的 300 ms 防连点锁。

## 6. 响应时机（→ 本作“应对窗口”）

### 6.1 参考游戏怎么做的

- **万智牌 Arena**：默认**自动传递优先权**——只要你没有可打出的东西，客户端直接跳过 [S8][S9]。玩家可以在阶段条上点亮“停止点”（我方回合橙色、对方回合蓝色），在指定阶段强制停下 [S8]；按住 Ctrl 获得临时“完全控制”，Ctrl+Shift 锁定完全控制 [S8]；Enter 表示“传递直到出现可回应的事件” [S8]。堆叠显示在屏幕右侧，悬停可看目标，堆叠过大时移到屏幕中央 [S9]。单次行动超时会出现 30 s 的燃绳，超时两次自动判负 [S10]。
- **游戏王 Master Duel**：“发动确认”分 关/自动/开 三档——“关”仅对强制效果询问；“自动”在对手召唤、攻击宣言、发动卡片、回合结束前等关键时点询问；“开”在每个阶段变更、效果结算后等所有时点询问；可按住左键临时切“开”、按住右键临时切“关” [S11]。
- **三国杀**：出“闪”“无懈可击”等响应有读条倒计时；官方攻略指出，客户端的无懈读条方式会**泄露信息**——“有读条就有（无懈），无读条就没有” [S32]。
- **符文之地传说**：快速法术可在对手行动后回应，先知之眼可预览结算结果 [S13]。

### 6.2 为什么这样做

- 自动跳过是为了节奏：大部分时候玩家无牌可应，每次都弹窗会让敌方回合冗长（Master Duel 玩家对频繁弹窗 + 计时器的抱怨即反例 [S11]）。
- 停止点/全控是给高手的“精确度”——代价是复杂度。
- 倒计时保证联机公平；单机里它的作用变为“提醒并推进节奏”，因此应可调或关闭。
- 三国杀的教训：**窗口是否出现本身就是信息**。本作是 PvE，信息泄露不影响公平，但会影响“节奏一致性”——有应牌时敌方行动明显停顿，没有时一闪而过。

### 6.3 本作怎么做

**触发逻辑（与 GDD 4.5 一致）**：敌方单位 **宣告** → 引擎检查玩家手中是否存在“当前可用余烬支付且有合法目标”的应牌 → 有且未设为自动跳过 → 打开窗口；否则直接结算。

**节奏统一**：无论窗口是否打开，每个敌方宣告都先播放 **450 ms 宣告演出**（意图图标放大脱离、箭头指向目标、宣告横幅），保证敌方回合节拍稳定，也让玩家看清“谁打谁”。

**窗口 UI**（z 层 80）：
- 棋盘蒙 30% 暗层，但攻击者、目标、箭头、我方主帅不被压暗（挖洞）。
- 中线区上方出现**宣告横幅**（x 660–1260，y 360–440）：“【锈甲将军】宣告：斩击 → 我方主帅 · 12 伤害”，右侧显示“若不应对：主帅 58 → 46”。
- 横幅下方为主按钮“不应对”（220×80，与结束回合按钮**同一位置**替换，保持肌肉记忆），外圈为**倒计时环**：默认 8 s，环由金变朱，最后 3 s 每秒一次轻微脉冲；到时自动“不应对”（不自动出牌）。
- 手牌：可支付的应牌上抬 40px + 朱印发光；其余手牌降暗 50% 并下沉。
- 源盘：余烬槽高亮，悬停应牌时预览将消耗的余烬。
- 悬停应牌 → 在宣告横幅右侧显示“应对后”预览（如“主帅受到 0 伤害 · 反击 6”），这是 LoR 先知之眼的做法 [S13]。
- 打出应牌后窗口计时暂停，进入连锁显示。

**连锁（LIFO，深度 ≤ 4）**：中线区显示竖向“连锁栈”，最底一层为敌方宣告，每层 400×64 的横条（来源头像 + 效果一行摘要 + 目标箭头），新层从上方压入（200 ms），结算时自上而下逐层弹出并闪光（每层 350 ms）。有手牌的首领对玩家应牌再应对时，同样以横条压栈，并再次开放玩家窗口（倒计时重置）。

**设置项（设置 → 战斗 → 应对）**：
1. **应对询问**：`总是询问`（有可付应牌即开窗）/ `智能`（默认：仅当应牌能改变本次结算结果时——例如能让伤害减少、取消、改目标——才开窗）/ `从不`（全部自动跳过）。对应 Master Duel 的 开/自动/关 三档 [S11]。
2. **倒计时**：5 s / 8 s（默认）/ 12 s / 无限。
3. **按类型停止**（对应 MTGA 停止点 [S8]）：攻击我方主帅时 ✔ / 攻击我方单位时 ✔ / 敌方施法时 ✔ / 敌方增益防御时 ✘。
4. **临时覆盖**：敌方回合中按住 Shift = 本次必定询问；按住 Ctrl = 本回合全部跳过。屏幕右下（结束按钮上方）常驻一个小的“应对模式”三态开关（询问/智能/跳过），点击循环切换，与 Master Duel 的“Switch”方式一致 [S11]。

**新手引导**：第一幕精英战（GDD 10）首次开窗时倒计时暂停，箭头指引“这张牌可以现在打出”。

## 7. 判定与牌堆操控

### 7.1 参考游戏怎么做的

- **三国杀（规则层）**：每名角色有手牌区、装备区（武器/防具/+1 马/−1 马/宝物五个固定位，正面朝上）与**判定区**（延时锦囊放置处，正面朝上）；另有牌堆（背面）、弃牌堆（正面）与“处理区” [S30]。延时锦囊在目标的判定阶段逐张判定：乐不思蜀非红桃则跳过出牌、兵粮寸断非梅花则跳过摸牌、闪电黑桃 2–9 受 3 点雷伤否则传给下家 [S48]。
- **三国杀（界面层）**：延时锦囊以小图标挂在武将框旁；判定时判定牌在屏幕中央（处理区）翻开展示。长期状态以“武将牌上/旁的牌”呈现，解决实体版要靠记忆的问题 [S31]。
- **观星**：界·诸葛亮“观看牌堆顶五张（存活人数 <4 时三张），以任意顺序放回牌堆顶或牌堆底”[S33]。据玩家问答的搜索摘要，移动端界面为**两行：第一行代表牌堆顶，第二行代表牌堆底，把想要的牌拖到顶行前面、不要的拖到底行** [S34]。
- **炉石**：“发现”三选一居中展示；牌库悬停只显示剩余张数 [S18]。

### 7.2 为什么这样做

- 判定区正面朝上 = 公开信息，让所有人都能计算“下回合会判什么”。
- 居中翻牌 = 仪式感 + 所有人同时看到结果。
- 观星的“两行”是把抽象的“顶/底”映射成空间位置，拖拽即排序，零学习成本。

## 8. 敌人意图

### 8.1 参考游戏怎么做的

- **杀戮尖塔 1**：意图图标悬浮在敌人头顶。攻击 = 红色武器 + 下方数字，数字即将造成的伤害，已计入玩家易伤、敌人虚弱等修正；**武器图标随伤害分 7 档（0–4、5–9、10–14、15–19、20–24、25–29、30+）从匕首升级到镰刀**；防御 = 盾；增益 = 蓝色上箭头；减益 = 红/紫色下箭头；另有逃跑、睡眠/眩晕、未知（分裂、自爆、召唤、重生、无动作等）；多个意图合成一个组合图标（攻击+增益等）[S5]。遗物“符文圆顶”以“全部显示未知”换取能量 [S5]。
- **杀戮尖塔 2**：攻击档位改为 0–4、5–9、10–19、20–39、40+；**多个意图不再合并，而是并排显示多个图标**；新增召唤、治疗、给卡牌施加苦痛、塞入状态牌、自爆等意图 [S6]。
- 攻击多段显示为“伤害×次数”。

### 8.2 为什么这样做

- 公开意图把“猜”变成“解题”：玩家每回合都在做“防多少、打多少”的精确计算。
- 数字必须是**最终值**，否则玩家要心算，意图就失去意义。
- 图标分档让“危险程度”在不读数字时就能被感知。
- 尖塔 2 拆分组合图标：组合图标数量爆炸且难以学习，拆开后每个图标语义单一。

### 8.3 本作怎么做

**图标语义（GDD 9 已定，这里补充视觉规格）**：

| 意图 | 图标 | 主色 | 数字 |
|---|---|---|---|
| 攻击 | 兵刃，按最终伤害 5 档：0–4 匕、5–9 刀、10–19 剑、20–39 戟、40+ 陌刀（沿用尖塔 2 分档 [S6]） | 朱红 | `12` 或 `6×3`（多段） |
| 防御 | 盾 | 玄青 | 护甲值 |
| 增益 | 上箭头 + 金光 | 鎏金 | 无（悬停看详情） |
| 减益 | 下箭头 + 紫雾 | 绛紫 | 无 |
| 召唤 | 阵纹 | 翠青 | 召唤数量 |
| 判定 | 命牌 | 随命纹条件 | 延时回合数 |
| 施法 | 手牌 + 张数（首领） | 素白 | 张数 |
| 逃跑 / 眩晕 / 冰冻失效 | 足迹 / 星环 / 冰裂叉 | 灰 | —— |
| 未知 | 问号 | 灰 | —— |

- **多意图并排**（尖塔 2 做法），最多 3 个，每个 56×56；数字 28px 粗体、黑描边 3px，右下对齐。
- **位置**：敌方单位 token **朝向中线一侧（左缘）上方**，外探 16px 进入中线区，避免被右侧相邻列遮挡；敌方首领/主帅意图在其立绘上方。
- **目标可视化（本作双排战线的关键补充）**：尖塔只有一个玩家目标，本作敌人可以打前阵任一单位或主帅，所以：
  - 被瞄准的我方单位/主帅上方显示朱红“来袭签”：`⚔12`，同一目标多个来袭时合并为总和 `⚔18 (2)`；
  - 悬停敌方意图 → 画出虚线弧指向其目标，并显示“目标：前阵 2 号【山魈】”；
  - 我方主帅血条显示“预计承受”虚影段：`来袭总和 − 当前护甲`，数字“预计 −12”。
  - 意图目标为“结算时再选”的（如随机目标），来袭签显示为“⚔12 ?”并在悬停中说明规则。
- **实时重算**：玩家打出减益/护甲/移位后，意图数字与来袭签在 150 ms 内以“数字滚动”更新，颜色短暂变为翠绿（变好）或朱红（变坏），直接反馈操作价值。
- **意图生成**：敌方回合结束时新意图从单位身上“浮现”，依次 80 ms 错峰，200 ms 淡入 + 轻微下落。
- **执行时**：意图图标先放大 1.3× 脱离（这就是 §6 的 450 ms 宣告演出的一部分），执行完消失。

## 9. 地图界面

### 9.1 参考游戏怎么做的

- **杀戮尖塔 1**：纵向卷动，从下往上爬塔；7×15 网格、随机路径，第 1 层全为普通战斗、第 9 层全为宝箱、第 15 层全为营地，第 16 层为首领；精英/营地第 6 层起才出现，精英/商店/营地不能连续 [S27]。原版节点图标**全为黑色、部分形状相近**，识读费力 [S50]。

- **三国杀**无地图，不参考。

### 9.2 为什么这样做

- 路线规划是 roguelike 的主要策略层之一，玩家需要一眼看出“这条路有几个精英、几个营地”。
- 颜色 + 形状双编码让“扫视计数”变快（尖塔 2 的明确动机 [S7]）。
- 画线标注把玩家脑内的规划外化，降低回看成本。

### 9.3 本作怎么做

**方向：横向卷动，左→右推进**（横屏的长边给层数；也契合“手卷”展开的画意）。每幕 15 层 + 首领，7 行（GDD 的“7 列”在横向地图中转为 7 行）。

- 卷动：鼠标滚轮/拖拽/方向键；移动端单指拖动 + 惯性。右上角缩略条显示全幕进度。
- **节点图标**（64×64，热区 96×96；紧凑档热区 ≥122dpx）：

| 普通战斗 | 交叉刀 | 墨黑 |

- **路径可读性**：已走路径 = 实墨线 6px；可前往的下一层节点 = 金色呼吸光圈 + 连线高亮；不可达节点 = 40% 透明；悬停某节点时，从当前点到该节点的**所有可达路径**高亮，并在屏幕底部显示“此路线：精英 2 · 营地 1 · 商店 1”。

### 10.3 本作怎么做

**战后奖励面板**（§14.3 线框）：竖列奖励条，每条 560×88：图标 + 名称 + 状态（未领取/已领取）。卡牌奖励条点击后进入三选一。

**商店**（§14.4 线框）：
- 上区：7 张卡（5 张主/副色 + 2 张中立），L2 尺寸，价格签在卡下方；随机一张打 5 折，旧价划线 + 朱红“半价”签。

### 12.1 参考游戏怎么做的

- **炉石**：左侧“历史栏”以图标形式记录最近的出牌与攻击，悬停展开详情；关键词悬停后弹出说明 [S20]；棋盘遵循“左 = 过去（历史）、中 = 现在、右 = 未来（牌库/结束按钮）”的空间叙事 [S4]。

- **万智牌 Arena**：堆叠显示在右侧，悬停可看目标，右键看完整卡牌 [S9]。
- **杀戮尖塔**：意图数字即伤害预览；攻击牌在悬停敌人时卡面数字实时变化（已计入易伤/虚弱）[S5]。

### 12.2 为什么这样做

- 预览优先于日志：玩家更需要“接下来会发生什么”而不是“刚才发生了什么”。
- 日志是“事后解释”，在连锁/触发队列复杂时避免“我怎么死的”的困惑。
- 提示框必须按需出现且不遮挡目标本身。

### 12.3 本作怎么做：五级信息层级

| 级 | 内容 | 触发 | 位置 | 延迟 |
|---|---|---|---|---|
| 1 常驻 | 生命、护甲、攻/体、费用、意图数字、来袭签、牌堆张数、源/余烬 | 始终 | 元素本体 | —— |
| 2 内联预览 | 目标血条虚影、卡面数字随目标变化、“预计 −12”、击杀标记、反击预览 | 拖动/悬停目标 | 目标本体上 | 0 ms |
| 3 提示框 | 关键词、状态、意图详情、遗物说明 | 悬停 | 目标**朝中线一侧**；卡在右半屏时向左弹 | 300 ms（关键词），遗物 150 ms |
| 4 检视 | L0 大卡 + 全部关键词 + 衍生牌 + 升级对比 | 右键/长按 350 ms | 屏幕中央模态 | —— |
| 5 战报 | 全部结算记录 | 顶栏“战报”按钮 / L 键 | 右侧抽屉 | —— |

**伤害预览细节**：
- 攻击牌卡面数字：悬停/瞄准目标时实时变为最终值（计入锋锐、虚弱、易伤），增大用翠绿、减小用朱红（尖塔惯例）。
- 目标血条：护甲段（玄青）先被扣、再扣生命段（朱红虚影闪烁 0.8 s 周期），灵障会以“符箓破碎”小图标显示“抵消此次”。
- 攻击单位时：同时在我方攻击者上显示反击虚影（【远射】则显示“无反击”小字）。
- 断魂：对单位显示“断魂 · 必杀”，对主帅显示 “+3”。

**关键词提示框**：
- 宽 320，内边距 12，标题 16px 加粗（关键词名着其所属色），正文 14px；多个关键词竖向堆叠，最多 4 个，再多则显示“+2（按住 Shift 展开）”。
- 嵌套关键词（提示中又出现关键词）：按住 Shift 或移动端“钉住”按钮将提示锁定，再悬停其中的关键词打开二级提示（最多两级）。
- 所有关键词在规则文字中下划点线，图标与文字同色。

**战报抽屉**：宽 420，x 1500–1920，y 128–760，半透明墨底 88%；每条一行“图标 + 主语 → 动作 → 对象 · 数值”，按回合分组，连锁以缩进显示；判定条目显示命纹小图；悬停条目时在棋盘上高亮涉及的单位。默认折叠，最近 1 条会以 2 s 的“行动横幅”显示在中线区顶部（y 128–168），不需要打开抽屉。

**防遮挡规则**：提示框永不覆盖：被悬停对象本身、拖拽箭头的目标、主帅血条、结束按钮。

## 13. 演出节奏

### 13.1 参考游戏怎么做的

- **炉石**：传说卡带龙形边框，登场有专属入场动画、音乐与语音 [S45]；回合 75 s，剩 20 s 出现燃绳 [S18]。Derek Sakamoto 在 GDC 2015 的演讲强调“我们的游戏就是 UI”，所有界面都应有实体感（盒子、托盘、钥匙）[S1][S2][S3]。
- **Marvel Snap**：每回合揭示顺序由“当前领先方先揭示”决定，**顶部名字发橙光的一方先揭示** —— 用 UI 提前告知演出顺序 [S39]。
- **游戏手感研究**：命中停顿（hit-stop）通常 40–80 ms 即足以表现重量；屏幕震动 0.1–0.3 s、几个像素后快速回稳；交互“手感”的关键在操作后 400 ms 内界面如何回应 [S44]。
- **杀戮尖塔**：Neow 开局、首领战前地图上即显示首领肖像；幕间以宝箱/首领遗物做节奏收束 [S49][S27]。

### 13.2 为什么这样做

- 演出为“重要时刻”服务，频繁动作必须短（< 500 ms），罕见动作可以长（1–3 s），但都要可跳过。
- 提前告知顺序（Snap）能让玩家把演出当“信息”看，而不是等待。

### 13.3 本作怎么做：时长表（标准速度 1.0×）

| 事件 | 总长 | 分解 | 可跳过 |
|---|---|---|---|
| 我方回合开始横幅 | 700 ms | 墨笔横扫 250 + 停留 300 + 淡出 150 | 点击即过 |
| 敌方回合开始横幅 | 600 ms | 同上，玄青色 | 同上 |
| 普通出牌（策略） | 450 ms | 飞至预备位 180 + 生效闪光 150 + 进弃牌堆 120 | 否（很短） |
| 普通攻击 | 520 ms | 前冲 160 + 命中 hit-stop 60 + 伤害数字 + 回位 200 | —— |

**布局理由摘要**
- 左 = 我方（过去/资源：抽牌堆、源盘），右 = 敌方与“推进”（结束回合、弃牌堆），与炉石“左过去、中现在、右未来”的空间叙事一致 [S4]。
- 天命区位于**中线正上方**：双方共享 → 放在中立位置；判定大牌落在正中，双方的视线交汇点。
- 源盘与手牌同处底部左侧：出牌时视线在“手牌 ↔ 源”间移动最短（GDKeys 所说的“减少视线移动” [S4]）。
- 结束回合与“不应对”共用同一坐标：敌我回合使用同一个“推进”按钮位置。
- 敌方意图全部落在“朝向我方的一侧”，玩家视线从我方前阵向右看时先读到意图。

**状态切换对布局的影响**
- 拖牌：手牌下沉 60px（§2.3），我方空格亮起。
- 敌方回合：手牌整体下沉 40px 并降暗到 70%（仍可悬停查看），应牌保持原亮度并带朱印高光。
- 应对窗口：见 §6.3；z 80 暗层挖洞保留攻击者、目标、我方主帅、源盘余烬、手中可用应牌。
- 判定：z 80 暗层 40%，仅判定大牌、判定原因、判定目标高亮。

## 15. 移动端横屏适配

### 15.1 尺寸换算（决定一切的数字）

设计坐标到物理 pt 的比例 `s = 屏幕可用高度(pt) / 1080`（16:9 以高度适配）：

| 设备（横屏） | 可用高度 | s | 44pt 对应 dpx | 12pt 字对应 dpx |
|---|---|---|---|---|
| iPhone 14/15（844×390pt） | 390 | 0.361 | **122** | 33 |
| 大屏安卓（≈915×412dp） | 412 | 0.381 | 115（48dp → 126） | 31 |
| iPad 11"（1194×834pt，16:9 以宽适配 → 高 672） | 672 | 0.622 | 71 | 19 |
| 桌面 1080p | —— | 1.0 | 44（鼠标无此约束） | 12 |

- Apple HIG 建议触控目标 ≥ 44×44pt [S42]；Material 建议 ≥ 48×48dp、目标间距 ≥ 8dp，图标可小于热区、用透明内边距补足 [S41]。
- **规则**：可用高度 < 500pt 时启用“紧凑档”；≥ 500pt（平板）沿用桌面布局，但所有热区外扩到 ≥ 72dpx。

### 15.2 紧凑档布局差异

| 元素 | 桌面 | 紧凑档 |
|---|---|---|
| 顶栏 | h80，全部按钮 | h110；只留 生命、金币、消耗品 ×3（每格 110×100）、菜单按钮（牌组/地图/图鉴/设置/战报收入菜单） |
| 遗物栏 | 常驻一行 | 收为顶栏“遗物(12)”按钮 → 底部抽屉网格；战斗中触发的遗物以左上 Toast 闪现 |
| 单位热区 | token 本体 | 整个格子（146×150dpx ≈ 53×54pt）✔ |
| 意图 | 56dpx | 72dpx 视觉；点单位即显示意图详情 |
| 手牌 | L2 扇形 | L4 直线，露 60%，点区域展开（§2.3） |
| 结束回合 | 220×80 | 260×130 |
| 献台 | 96×116 | 132×150 |
| 牌堆 | 108×152 | 130×170 |
| 源宝石 | Ø40 | Ø44（不需单独点选；点源盘整体打开详情） |
| 规则文字 | 卡面 13px | 卡面不显示；详情条 / 检视中 ≥ 34dpx |
| 提示框 | 悬停 300ms | 长按显示，松手后保持“钉住”，点空白关闭 |
| 应对倒计时 | 8 s | 默认 10 s（触屏多一步操作） |

### 15.3 触控交互规范

- **点选 + 点目标**：点卡 → 选中；合法目标高亮；点目标 → 目标上方“确认”气泡（可关）→ 确认。点空白或点已选卡取消。
- **拖拽**：移动 ≥ 12dpx 才判定为拖拽，避免与点击冲突；拖拽中手指上方 120dpx 显示放大的卡片/箭头终点（手指不遮挡）。
- **长按**：350 ms（可在设置中调 250–600 ms）= 检视/提示；长按过程中显示环形进度，给出“即将触发”的反馈。
- **不用双击、不用多指手势**（地图缩放除外，地图可双指缩放 0.7–1.3×）。
- **安全区**：HUD 锚定到安全区内；刘海/挖孔一侧只放背景。
- **性能**：移动端粒子数量上限减半、判定光效使用预烘焙序列帧；PixiJS `resolution` 取 `min(devicePixelRatio, 2)`。

## 16. 实现备注（PixiJS）

- **文本**：卡面规则文字使用 `BitmapText` 或预烘焙 `Text` 纹理（悬停放大时切换到更高分辨率版本，避免 1.5× 放大发虚）；中文字体需子集化。
- **手牌热区**：按 §2.3 使用常态布局的静态矩形做命中测试，不依赖放大后精灵的 bounds。
- **箭头**：每帧按贝塞尔采样 14 个点放置燕尾精灵，偏移量随时间累加实现“流动”。
- **暗层挖洞**：z 80 暗层用 `Graphics` 画全屏矩形，用 `mask`/`cut` 挖出高亮对象的圆角矩形。
- **演出调度**：所有演出挂在一个时间线队列上，受“演出速度”全局倍率控制；引擎结算与表现解耦（引擎一次性给出事件序列，表现层按序播放），这也保证了 GDD 13 的确定性回放。
